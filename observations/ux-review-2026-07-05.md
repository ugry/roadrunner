# Insucar — UX & Accessibility Review
Date: 2026-07-05

## Scope
Review of prototype HTML pages: `enduser.html` (467 lines), `operator.html` (1176 lines), `landing.html` (1154 lines), `admin.html` (168 lines), `register.html`, `status.html`, `cognito-callback.html`.

## Mobile-First UX Assessment

### Strengths

1. **Viewport properly set:** All pages have `<meta name="viewport" content="width=device-width,initial-scale=1">` — correct
2. **Responsive grid patterns:** `enduser.html` uses `.grid2` with `@media(max-width:640px)` fallback to single column (line 37)
3. **Dark mode support:** `@media(prefers-color-scheme:dark)` implemented in enduser.html (lines 52-53) and landing.html
4. **High contrast mode:** `@media(prefers-contrast:more)` in enduser.html (line 51)
5. **Battery-aware power saving:** enduser.html:232-242 checks battery level and adjusts polling frequency
6. **Offline queue:** LocalStorage-based incident queue for low-connectivity scenarios (enduser.html:245-253)
7. **Hold-to-confirm pattern:** Prevents accidental incident submission (enduser.html:174-188)
8. **Voice guidance:** Web Speech API integration for hands-free incident reporting (enduser.html:400-414)
9. **Emergency panic mode:** One-tap escalation for dangerous situations (enduser.html:201-207)
10. **Multi-language support:** Phrase cards in EN/FR/DE/ES + basic i18n dictionary (enduser.html:436-465)
11. **Photo capture:** Camera with `capture="environment"` attribute for scene photos (enduser.html:108)
12. **GPS auto-detection:** Background geolocation fetch on page load (enduser.html:219-228)
13. **Dark mode toggle:** User-controlled dark/light switch with persistence (enduser.html:254-263)
14. **Service Worker:** Registered for offline/PWA capabilities (enduser.html:388-397)
15. **Push notification subscription:** Web-push integration scaffolded (enduser.html:392-394)

### Weaknesses & Recommendations

#### WCAG 2.1 Compliance Gaps

| # | Issue | WCAG Criterion | Severity | Fix |
|---|-------|---------------|----------|-----|
| 1 | **Missing alt text on SVG logo** | 1.1.1 Non-text Content | High | Add `role="img"` + `<title>` to inline SVG in bar |
| 2 | **Color-only status indicators** | 1.4.1 Use of Color | High | Status pills rely solely on color (.pill green). Add text labels or icons |
| 3 | **No skip-to-content link** | 2.4.1 Bypass Blocks | Medium | Add `<a href="#main">Skip to content</a>` |
| 4 | **Missing `<label>` associations** | 1.3.1 Info and Relationships | Medium | Some inputs have labels but may lack explicit `for`/`id` linking |
| 5 | **Emoji as icons without aria-label** | 1.1.1 Non-text Content | Medium | Panic button uses emoji (🆘) without text alternative for screen readers |
| 6 | **Focus indicators insufficient** | 2.4.7 Focus Visible | High | `:focus-visible` uses `outline-offset:2px` with brand color — good but may be too subtle on dark backgrounds |
| 7 | **No ARIA landmarks** | 1.3.1 Info and Relationships | High | No `<main>`, `<nav>`, `<header>`, `<footer>` roles. All content in generic `<div>` |
| 8 | **Tab order may be illogical** | 2.4.3 Focus Order | Medium | Wizard steps hidden with `display:none` — when revealed, focus jumps unexpectedly |
| 9 | **Status messages not announced** | 4.1.3 Status Messages | Medium | `showBanner()` adds DOM elements without `role="alert"` or `aria-live` |
| 10 | **Toast banners not accessible** | 1.3.1, 4.1.2 | High | Banner div lacks `role="alert"` — screen readers won't announce |
| 11 | **Keyboard navigation gaps** | 2.1.1 Keyboard | High | Hold-to-submit (mousedown/mouseup) has no keyboard equivalent |
| 12 | **Missing lang attribute on mixed-language content** | 3.1.2 Language of Parts | Low | French/German/Spanish phrases should wrap in `<span lang="fr">` etc. |
| 13 | **Color contrast** | 1.4.3 Contrast (Minimum) | Medium | `.muted` color `#5b7183` on `#f4f8f6` = 4.67:1 (passes). Dark mode: `#7a8fa0` on `#0b1f2a` = ~4.0:1 (may fail for small text) |
| 14 | **Text resize** | 1.4.4 Resize Text | Low | Uses `px` for most sizes — should use `rem`/`em` for Zoom compatibility |
| 15 | **Touch target size** | 2.5.5 Target Size | Medium | Small buttons like "EN/FR/DE" phrase buttons are only ~24px — below 44px recommended |

#### UX Flow Improvements

1. **Landing page (landing.html):** Beautiful Stripe-inspired design with golden-ratio spacing. Excellent hero, mobile responsive. **Missing:** No clear CTA for "broken down now" scenario. Being stranded is an emergency — the help-now path should be prominent.

2. **Registration:** Good server-side validation. **Missing:** Password strength indicator, email confirmation field, terms acceptance checkbox visibility.

3. **Incident wizard:** Excellent 4-step wizard pattern. **Improvements:**
   - Step 1 (What happened): Good incident type selection
   - Step 2 (Where): GPS auto-detection is excellent. what3words integration is forward-thinking
   - Step 3 (Describe): Phrase cards are brilliant for stressed users. **Missing:** Step shows panic button but could be more prominent
   - Step 4 (Confirm): Hold-to-submit is excellent for preventing accidents. **Improvement:** Add keyboard-only equivalent

4. **Post-submission tracking:** Live ETA view with driver info is excellent. **Missing:** Map integration (Leaflet available but not used in enduser.html)

5. **Operator console (operator.html):** Professional dark theme, Live queue with SSE, auto-refresh. **Missing (from operator-gui-research.md gap list):**
   - Keyboard shortcuts for power users
   - Drag-and-drop or one-click dispatch
   - SLA/aging timers on queue items
   - Color-coded status system (currently basic)
   - Supervisor escalation/barge-in button

## Accessibility Quick Wins (by effort)

### Low Effort, High Impact
1. Add `role="alert"` to toast banner in showBanner()
2. Add `<main>` landmark to content area
3. Add skip-to-content link
4. Add `aria-label` to emoji panic button
5. Add explicit `for`/`id` on form labels
6. Increase touch target size on small buttons (min 44px)

### Medium Effort, High Impact
7. Add keyboard support for hold-to-submit pattern
8. Add `aria-live` region for status updates
9. Add `<nav>` landmark for navigation
10. Add keyboard shortcuts for operator console
11. Add focus management for wizard steps

### Higher Effort
12. Replace px-based font sizes with rem
13. Add comprehensive ARIA labels to operator console
14. Add screen reader testing + accessibility audit
